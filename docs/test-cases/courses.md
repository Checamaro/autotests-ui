# Тест-кейсы: courses (создание и редактирование курса)

Страницы: `#/courses/create` (создание) и `#/courses/<id>` (редактирование, заголовок «Update course») —
один компонент `CreateCoursePage`. Источник требований: отчёт ui-requirements-analyst, исходники
`src/Views/Courses/CreateCourseToolbarView.tsx`, `src/Pages/Courses/CreateCoursePage.tsx`.
Кейсы загружены в Qase: проект `UI`, suite `courses` (id 1). CC-N соответствует UI-N.
Все кейсы выполняются в состоянии «зарегистрирован и вошёл» (`chromium_page_with_state`), если не сказано иное.
Доступ гостя на эти маршруты (редирект на логин) уже описан в authorization.md, кейс 9, — здесь не дублируется.

## Общие данные
- Пользователь: `settings.test_user` (через фикстуру состояния).
- Базовый курс «D-base»: title `Playwright`, description `Playwright`, estimated time `2 weeks`,
  min score `10`, max score `100`, превью `settings.test_data.image_png_file` (как в существующих тестах).
- Значения полей вводить через `fill`, не посимвольно (ввод десятичной точки в числовом поле нестабилен).
- «Кнопка сохранения» — кнопка в тулбаре страницы (`click_create_course_button`), одна и та же на create и edit.

## Предусловия для autotest-writer (не хватает в page objects)
1. Проверка заголовка страницы «Create course» / «Update course».
2. `check_enabled` / `check_disabled` для кнопки сохранения (проверить, что уже есть, иначе добавить в элемент `Button`).
3. Частичное заполнение формы: `fill` с необязательными аргументами (сейчас заполняются все 5 полей разом).
4. Методы упражнений на `CreateCoursePage`: добавить, удалить по индексу, проверить подпись `#N Exercise`,
   проверить значения полей, количество упражнений.
5. Очистка поля (`fill("")`) для числовых полей и проверка значения «0».
6. Фабрика курса через UI (создать курс и вернуться на список) — общая фикстура для кейсов edit.
